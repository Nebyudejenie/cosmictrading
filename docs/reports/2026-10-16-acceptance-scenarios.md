# Mandatory scenarios (owner's directive, Phase 11) — expected behaviour, tests, result

For each scenario the directive lists: what the system must do, the automated tests that show it, and what is still missing.

- **Result:** every test named here passes in `make check` (see `IMPLEMENTATION-STATUS.md` S17 for the run and its count).
- **Basis:**
  - unless stated otherwise, the tests run the real code against PostgreSQL;
  - the trading tests use the paper simulator with injected faults, or the MT5 emulator driving the real bridge program.
- **Outside pytest:** a real process kill and restart is exercised by `scripts/local-verify.sh` (`--phase chaos` and `restart`).
- Test files are under `tests/`.

## What this run changed

- **Three defects were fixed:**
  - A malformed Telegram callback raised an unhandled error. It is now refused as "Unknown action."
  - The job-history read at worker start would have crashed a worker started during a database outage. It is now best-effort.
  - An approved trade that could not reach the venue failed without telling the owner. It is now reported with the reason, and so is every rejection.
- **A protection gap was closed:** a protective order ended at the venue without our asking (by hand in the venue's app, by the venue, or by someone with access) was replaced silently. Now it also raises a WARNING incident that asks the owner to check the account's access.

## Not claimed

Passing these tests does not make the system production-ready for real money. Live trading stays disabled until go-live gates A–I and a separate owner activation. Several scenarios are proven on the paper simulator or the MT5 emulator only. On the real venues, only these are verified so far:
- the HFM demo contract (with an attached stop on a resting order);
- the Binance test network contract.

No real test-network or demo fill has happened yet.
